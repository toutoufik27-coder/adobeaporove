# منظّف الفيكتور — SVG Geometry Restoration & Professional Reconstruction Engine

محرك يستقبل ملف SVG موجوداً (غالباً ناتج تحويل PNG / JPG / WebP / صور الذكاء الاصطناعي إلى فيكتور)، يكتشف المشاكل الهندسية، ثم يعيد بناء ما يمكن تحسينه **بأمان**.
ليس ضاغط SVG، ولا غلافاً لـ SVGO، ولا مبسّط مسارات.

كل تعديل يمر بنفس الدورة:

**تحليل ← اقتراح (Candidate) ← مقارنة مع الأصل ← حساب الخطأ ← قبول / رفض**

إذا لم يكن التحسين آمناً يبقى المسار الأصلي كما هو، ويُسجَّل سبب الرفض.

## التشغيل

- **المتصفح:** في جذر المشروع شغّل `python -m http.server 8000` ثم افتح `http://localhost:8000/refine/`.
- **سطر الأوامر** (Node 18+ بدون أي مكتبات):
  ```
  node cli.js in.svg                                   # تحليل + توصية فقط
  node cli.js in.svg out.svg                           # المعالجة المقترحة
  node cli.js in.svg out.svg --mode professional --minify --report r.json
      --mode safe|balanced|professional|aggressive
      --stage Original|Cleaned|Simplified|Reconstructed|Shapes|Final
      --precision adaptive|2|3|4   --flatten-transforms   --no-structure   --force
  npm test
  ```

## البنية

| الملف | الدور |
|---|---|
| `src/xml.js` | محلل XML صارم (بدون DOCTYPE أو entities) ومُسلسِل يحافظ على ترتيب الخصائص |
| `src/security.js` | الملف غير موثوق: حذف script و foreignObject و on* و javascript: والروابط الخارجية و CSS @import/url() |
| `src/css.js` | الأنماط: خصائص العرض ← قواعد `<style>` (tag / .class / #id) ← style المضمّن، مع الوراثة |
| `src/matrix.js` | التحويلات: translate / scale / rotate / skew / matrix |
| `src/pathdata.js` | كل أوامر المسار (M L H V C S Q T A Z، مطلقة ونسبية) ← مقاطع أصلية (L, Q, C, A)، والكتابة بأقصر صيغة |
| `src/model.js` | نموذج هندسي لكل عنصر (path, rect, circle, ellipse, line, polyline, polygon, use): حدود، نمط محسوب، CTM، تعبئة/حد، قص/قناع، ترتيب؛ **نسخة أصلية مجمّدة لا تتغير** |
| `src/raster.js` | راسم مرجعي دقيق: nonzero/evenodd، الحدود (joins و caps)، clip-path، mask، الشفافية، التدرجات |
| `src/metrics.js` | محرك الفرق البصري: ΔE، نسبة البكسلات، الفرق المرئي (بعد تجاهل إزاحة أقل من المسموح)، البقع، SSIM |
| `src/features.js` | أنواع العقد (زاوية حادة / ناعمة / مستديرة / انتقال)، التعقيد، الطوبولوجيا، التعرف على الأشكال، الطابع العضوي، التناظر |
| `src/fit.js` | محرك الملاءمة: خط ← قوس ← منحنى تربيعي ← Bézier تكعيبي، الأبسط الذي يبقى ضمن التسامح |
| `src/engine.js` | نظام الاقتراحات، الثقة، التحقق الهندسي والطوبولوجي والبصري لكل منطقة، السجل، التاريخ |
| `src/passes.js` | المراحل العشر |
| `src/analyze.js` | تحليل الملف والتوصية |
| `src/process.js` | خط المعالجة، مراحل التاريخ، التقرير |
| `src/output.js` | كتابة النتيجة في نسخة من المستند الأصلي (العناصر غير المعدّلة تُكتب كما كانت) |
| `src/integrity.js` | فحص السلامة قبل التصدير |

## المراحل

1. **تنظيف البنية:** عناصر فارغة أو غير مرئية، حدود بلا مساحة، إغلاق حد مفتوح في شكل معبأ، أجزاء مغطاة بالكامل بأشكال أعلى.
2. **النقاط المكررة:** مقاطع بطول صفر ونقاط شبه مكررة.
3. **المقاطع الدقيقة:** العتبة ديناميكية (نسبة من الشكل ومن التصميم). يُفحص الطول والزوايا والجيران. التفاصيل الصغيرة محمية.
4. **النقاط على خط واحد:** والمقاطع المستقيمة الطويلة، بحسب أقصى انحراف.
5. **تحليل المنحنيات:** أنواع العقد، عضوي أو هندسي، الأهمية، التفاصيل، التناظر.
6. **ملاءمة المنحنيات:** بين الزوايا فقط. ثلاثة اقتراحات لكل حد (تسامح ضيق / الوضع / واسع)، ويُختار الأبسط الصالح. التسامح يتكيف مع حجم الشكل وأهميته، والأجزاء المخفية تحت أشكال أعلى تسامحها أكبر.
7. **التعرف على الأشكال:** دائرة، بيضوي، مستطيل، مستطيل بزوايا دائرية، مثلث، مضلع، مع حساب خطأ المركز وتباين نصف القطر والانحراف. الأشكال العضوية محمية. وتصحيح التناظر عند وجود دليل قوي فقط.
8. **تحقق الطوبولوجيا:** عدد الحدود والثقوب والمكونات والتداخل والتقاطعات الذاتية.
9. **التحقق البصري:** لكل شكل ثم للتصميم كاملاً. يُرجَع الحد أو الشكل المخالف فقط.
10. **التحسين النهائي:** دقة عشرية متكيفة، دمج المسارات المتطابقة المتجاورة، وتطبيق التحويلات (اختياري).

بعد كل مرحلة تُحفظ نسخة: الأصل ← التنظيف ← التبسيط ← إعادة بناء المنحنيات ← الأشكال ← النهائي. يمكن الرجوع لأي منها وتصديرها.

## الأوضاع

**آمنة، متوازنة، احترافية، قوية.** الوضع «القوية» يعني تسامحاً أكبر في التبسيط، لكن التحقق البصري يبقى قائماً في كل الأوضاع: ما يفشل فيه لا يُطبّق.
كل الإعدادات قابلة للتعديل من «إعدادات متقدمة»، مع زر لإعادة الافتراضي.

## ما يُحفظ دائماً

- الألوان والتدرجات (لا تتحول إلى لون واحد) والشفافية و fill-rule.
- الحدود (stroke) بكل خصائصها.
- المعرفات والفئات والمجموعات والمراجع.
- العناصر التي لا يمكن التحقق منها (`text` و `image`) تبقى كما هي.
- لا يُعدَّل مسار له خط متقطع أو markers أو بيانات مسار فيها خطأ.

## الواجهة

- عرض جنباً إلى جنب، وشريط مقارنة، وتراكب بشفافية لكل طبقة (مع وضع «الفرق»).
- التكبير: ملاءمة، و100% حتى 1600%، مع السحب والعجلة.
- فحص الهندسة: اضغط على أي شكل لترى عقده ونقاط التحكم والمقاطع والصندوق المحيط، للأصل وللنتيجة.
- المعالجة المقترحة بأرقام محسوبة فعلاً، وتقرير كامل، وسجل التعديلات المقبولة والمرفوضة مع أسبابها.
- تصدير منسّق أو مضغوط، مع أو بدون الحفاظ على البنية. إذا فشل فحص السلامة يُعطَّل التحميل العادي، ويبقى زر «تحميل رغم ذلك» مع تحذير.

## نتائج على ملفات حقيقية (الوضع الاحترافي)

- `samples/christmas-clock.svg`: من 1010 عقدة إلى 317، ومن 34 KB إلى 10 KB، والفرق المرئي 0.148% (بدون بقع).
- `samples/bakery-icon.svg`: من 225 إلى 151 عقدة، و6 دوائر أعيد بناؤها كدوائر حقيقية، والفرق المرئي 0.041%.
- 184 أيقونة من ملفات المستخدم: 0 أخطاء في فحص السلامة، وأسوأ فرق مرئي 0.2%. ناتج المحوّل الحالي نظيف أصلاً، لذلك التقليل فيها أقل.

## تصحيح المعنى بذكاء محلي

المحرك الهندسي يحافظ على التصميم ولا يعرف ماذا يرسم. أخطاء المعنى، مثل ساعة بـ14 علامة بدل 12، تأتي من مولّد الصور. لتصحيحها يعمل جزءان معاً:

1. **المحرك يقيس** (`src/structure.js`): يجد الأجزاء المتكررة (نفس الشكل في نفس الطبقة)، ويعرف كيف تترتب (على دائرة أو في صف)، ويعدّها بدقة، ويقيس انتظام التباعد. كما يربط العلامة المرسومة في طبقتين (شكل وثقب فوقه) كمجموعة واحدة.
2. **النموذج المحلي يفهم** (`src/ai.js`): يرى صورة الأيقونة مع المجموعات مرقّمة، ويجيب بـJSON فقط: ما هو الشيء، وما العدد الصحيح لكل مجموعة (أو «أي عدد مقبول»). النماذج الصغيرة ضعيفة في العدّ، لذلك لا نطلب منها أن تعدّ.
3. **المحرك ينفّذ** (`src/semantic.js`): يعيد رسم المجموعة بالعدد الصحيح وبتباعد متساوٍ، من علاماتها نفسها (نفس الشكل واللون والطبقة، مع تدوير كل علامة لتتجه نحو المركز). بعدها يتحقق أن لا شيء خارج المجموعة تغيّر.
4. **أنت تقرر**: كل اقتراح يظهر مع سببه، ويمكنك تعديل العدد يدوياً، أو العمل بدون نموذج أصلاً. التصحيح يُحفظ كمرحلة جديدة في التاريخ («تصحيح المعنى»).

**الخوادم المدعومة (محلية بالكامل):**
- **Ollama:** `ollama pull qwen2.5vl:7b` ثم `OLLAMA_ORIGINS=http://localhost:8000 ollama serve`.
- **LM Studio، llama.cpp server، Jan:** أي خادم بصيغة OpenAI. فعّل CORS من إعداداته.

**من سطر الأوامر:**
```
node cli.js clock.svg out.svg --ai http://localhost:11434 --model qwen2.5vl:7b --apply-semantic
```

**حالياً:** إعادة البناء تعمل للمجموعات الدائرية (علامات الساعة، الحبات حول إكليل، أطراف الثلج المنفصلة). الصفوف تُكتشف وتُعرض، لكن لا يُعاد بناؤها بعد. `test/mock-model.js` خادم تجريبي للاختبارات فقط، وليس نموذجاً حقيقياً.

## المطابقة مع الصورة الأصلية

بدون الصورة الأصلية، المرجع الوحيد هو الـSVG نفسه، فتبقى أخطاء التحويل كما هي (زاوية مستقيمة بدل قوس، أو طرف حاد بدل طرف مستدير). مع الصورة يصبح المرجع هو الصورة:

1. **إيجاد مكان الـSVG في الصورة** (`src/source.js`): إذا كان حجم الـSVG نفس حجم الصورة (ورقة كاملة) فالمطابقة مباشرة. أما الأيقونة المقصوصة من ورقة فيُبحث عن مكانها ومقياسها بالارتباط (correlation)، بدقة أقل من بكسل.
2. **إعادة الحواف** (`src/restore.js`): لكل حافة ظاهرة يُبحث في الصورة، عمودياً على الحافة، عن الحد الحقيقي بين لون الشكل واللون المجاور، ثم تُنقل الحافة إليه. بعدها يُعاد بناء الحد: الزوايا الحقيقية، ثم خطوط وأقواس ومنحنيات. الأجزاء المغطاة بأشكال أعلى لا تُلمس.
3. **القبول**: يُقبل التعديل فقط إذا قرّب الرسم من الصورة (متوسط ΔE والبكسلات الخاطئة)، وبدون تغيير في الطوبولوجيا أو تقاطعات جديدة.
4. **ما بعد المطابقة**: الرسم المصحح يصبح المرجع لبقية المراحل، حتى لا يُفسده التبسيط.

**في الواجهة:** زر «الصورة الأصلية (اختياري)»، أو اسحب الـSVG والصورة معاً. يمكن عرض الصورة الأصلية في اللوح الأيسر بجانب النتيجة، والتقرير يعرض نسبة البكسلات الخاطئة قبل وبعد.

**مثال** (`samples/deer-frame-icon.svg` مع `samples/deer-frame-source.png`): البكسلات الخاطئة من 3.93% إلى 3.82%. زاوية الإطار صارت قوساً كما في الصورة، وطرف الساق الحاد صار مستديراً. الجزء الأكبر من الخطأ الباقي سببه نعومة حواف JPEG، وليس خطأ في الرسم.
